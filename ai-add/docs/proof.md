# 固定协议下十位加法的认证

设输入每列数字为 `a_i,b_i∈{0,...,9}`，输入进位为 `c_i∈{0,1}`。模型每次都在空上下文上读取完全相同的五 token 模板，只改变这三个数字。它只需覆盖 `10×10×2=200` 种输入。

认证器对**实际权重、实际 CPU 后端、实际量化精度**运行全部 200 个 prompt，要求自由 argmax 生成数字 `d`、进位 `c_next` 和 `</think>`，并且：

```text
d + 10*c_next = a + b + c
```

三个 argmax 都要求相对第二名的 logit 间隔大于 0.0001。认证器把每种输入、输出及间隔写入 CSV，JSON 保存检查点指纹、参数量、精度和实际运行的后端列表。FNV-1a64 是文件一致性指纹，不是加密签名；复现脚本另存 SHA-256 的代码/可执行文件/权重清单。

交付 FP4 文件使用 `certify ... keep all`：加载 `final-fp4.cn` 后直接执行其中的打包权重，不重新量化。证书同时记录 MXFP4/FP8 的实际参数数量，避免把 FP32 检查或主权重重打包当成文件认证。FP4 模型包含 FP8 与 FP32 部分，其正确性覆盖这套实际混合精度执行路径。

初始进位 `c_0=0`。假设前 k 列成立，则：

```text
sum_{i<k}(a_i+b_i)*10^i
 = sum_{i<k} d_i*10^i + c_k*10^k
```

对第 k 列认证关系乘以 `10^k`，再相加，即得到 k+1 列关系。最后追加模型的最高进位，便得到所有输入列的正确和。对不足十位的输入，高位按零处理；前导零只影响格式，不影响值。最大输出为 `19999999998`。

这个证明依赖调度器使用认证过的固定 prompt、重置每列上下文、正确传递 cout、逐位扫描及倒序拼接。`add_predict()` 不读取真值表、不对两个操作数求和、不按输入查答案；它只调用 Transformer 并格式化输出。相同输入在固定环境中执行相同局部计算，因此全局位数不会引入新的未认证模型输入。

证书不保证采样模式的正确性，也不保证任意聊天 prompt 或改动权重后的行为。它是对当前浮点实现的穷举运行认证与程序归纳证明，未使用定理证明器验证 C 编译器/运行库。新机器、新精度、新模型都重新运行认证；CLI `add` 本身会在当前环境重新检查 200 种输入。
