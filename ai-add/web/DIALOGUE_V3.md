# 整式对话修复与实际训练（dialogue-v3）

当前默认是一个 user 整题问题，一个 assistant 自回归回答。之前默认 column-v2 以外部调度拆列，最后再拼接轨迹，不满足此目标，现已退出默认训练、推理及内置列表。旧权重留在项目与用户自己的本机检查点中，不改名成整式模型。

## 已改正的路径

- 默认模型、随机初始化、六阶段训练、数据预览与推理全部使用 chat-v1。
- 原始输出严格等于真实 prompt 加真实生成 token；不含 `# problem`、`# pos`、`scheduled` 或停止注解。停止原因、格式校验、滚动次数另放 JSON 与诊断区。
- user 只含 A+B；一个 assistant 思考块包含全部步骤，随后直接生成正序最终答案。推理没有拆位、传递进位、强制合法 token 或加法兜底；独立字符串加法仅评分。
- 未结束的思考块从实际 token 提取展示。格式失败和错误答案均可下载。
- 网络仍为 6 层、3+3 CED、dim24、57,388 参数；SWA/CSA2/MoE/Engram/mHC/RoPE 未替换。局部窗口 64→256，不增加参数，让完整十位训练对话仍可直接访问原题。
- SFT assistant 数字 token 权重 3，其他 token 权重 1，按回答权重归一化；prompt 无 CE。长课程前半程解锁五档，后半程重放全部长度。
- 网页只内嵌六个整式阶段；QAT 选择版本可能为 FP32。用户已有本机检查点继续保留，并标出旧逐列实验。

## 从零实训

固定种子 20261018，CoT，batch=4（包括 QAT）。共 15,800 次请求更新；RL 同奖励时跳过。训练约 12.9 分钟，含验证；不同机器耗时不同。

```powershell
ai-add/build/chat_run.exe ai-add/web/build/dialogue-v3-run 1 600 2400 4000 8000 200 600 4
python ai-add/web/publish-dialogue.py
python ai-add/web/test-dialogue-native.py
node ai-add/web/test-parity.cjs --dialogue
node ai-add/web/test-dialogue-wasm.cjs
```

固定 200 题用于选模，1/2/4/6/10 位各 40 题；部分边界题操作数实际更短（每组包含 0+0）。完整匹配包括全部 CoT 及结束标记，不是独立泛化结果。

|阶段|更新|选择步数|选择完整匹配|最后更新|按位数组的完整匹配|选择精度|
|---|---:|---:|---:|---:|---|---|
|1|600|600|0/200|0/200|[0, 0, 0, 0, 0]|FP32|
|2|2400|1400|25/200|25/200|[21, 1, 1, 1, 1]|FP32|
|3|4000|3400|47/200|47/200|[40, 4, 1, 1, 1]|FP32|
|4|8000|7800|74/200|71/200|[40, 28, 2, 2, 2]|FP32|
|5|200|0|74/200|72/200|[40, 28, 2, 2, 2]|FP32|
|6|600|0|74/200|64/200|[40, 28, 2, 2, 2]|FP32|

RL 200 轮中 69 轮有奖励差异，但最后完整匹配 72/200，选择阶段入口 74/200。FP4 QAT 最后 64/200，因此最终选择保留 FP32 的 74/200；没有把它标成 FP4 成品。训练前、真实最后、选择版本均保存在 `build/dialogue-v3-run/stage-N{-entry,-last,}.cn` 和同名 `.aiadd`，包含优化器及协议，可导入测试/续训。

## 独立自由生成测试

种子 938234，每长度 20 道非补零随机题；十位操作数均真实十位。模型无约束贪心连续生成，独立整数仅判对错。

|位数|正确 / 20|
|---:|---:|
|1|19/20|
|2|11/20|
|4|0/20|
|6|0/20|
|10|0/20|
|12|0/20|
|20|0/20|

这次修复的整式模型仍然没有学会通用十位加法，任意位泛化更未实现。旧模型的局部 200/200 不用于补足这个结果。

`99+1` 实际生成一个完整思考块和 `100`；`9999999999+1` 能生成正确答案，但不能代表随机十位能力。用户所举 `7140345462+1095133250` 本轮实际生成错误答案 `48233160523115`（应为 `8235478712`），网页明确判错并保留全文。错误主要已在读入/复制各列数字时出现，之后进位和最终答案也偏离；本轮不能把格式改正当成任务收敛。

## C / WASM 与交付验证

`build/parity-v3/report.json` 对照原生 scalar/auto 与实际交付 WASM scalar/SIMD，共 12 组，含整式 masked SFT、真实 RLOO（每组 6 次有效更新）、FP4 QAT、全部参数及 Adam m/v、模型互载。最大 logits 绝对差约 5.20e-5；容差等效，不声称 bit 相同或任意长期优化轨迹一致。

`test-dialogue-wasm.cjs` 对六阶段逐一运行，并要求短题、用户原题、十位进位和百位失败样例的实际生成 token 与 C 完全一致；另执行 CoT/无 CoT 六阶段更新和三版本检查点保存。

Windows CTest 15/15、Linux ASan/UBSan/leak CTest 15/15；这些包含引擎与旧兼容测试，不代表十位算术通过。独立模型成绩只看上表。原生完整生成与逐 token 原始文本证据在 `build/dialogue-v3-tests/`；自包含 HTML 验证与浏览器证据分别在 `validation-dialogue-delivery.json`、`browser-dialogue.json`。
