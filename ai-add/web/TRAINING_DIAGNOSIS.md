# 完整对话训练退化诊断（2026-10-18）

本文件记录前一次 chat-v1 自由生成失败实验。后来 column-v2 的外部逐列调度不符合整题单轮回答目标，现已退出默认路径；当前修复和实际训练见 [DIALOGUE_TRAINING.md](DIALOGUE_TRAINING.md)。

完整流程确实存在退化，既有课程代码错误，也有训练预算不足。已修复流程错误并完成前后两次六阶段复跑；**当前 57,388 参数的对话模型仍未学会通用十位加法**。阶段结束、验证选择和量化成功均不等于模型收敛。

## 复现与修复

1. 旧长课程以 `(step-1)*4/(total-1)` 选长度，十位只在最后一次更新出现。改成五个等长时间档解锁 1/2/4/6/10 位，3/4 选当前难度、1/4 重放已解锁长度；SFT 2 也重放一位含进位题。
2. RL/QAT 原来又从一位重走课程。现在从一开始混合全部五种长度。
3. 旧对话流程始终采用最后一次更新，覆盖阶段中曾经较好的模型。现在保存训练前、最后更新、验证选择三种版本。预训练保留最后更新；后续按完整匹配数优先、同分时验证 CE 更低选择，并用选中版本开始下一阶段。用户可以改为载入“最后更新”继续实验。
4. 四个 RL 回答奖励相同时，原来仍会执行熵、KL、AdamW。现在整次跳过，不让无优势信号的更新漂移；测试检查更新前后模型文件字节相同。有奖励差异时仍执行 RLOO、KL 和熵项。
5. 旧逐列协议的局部窗口只有 8 token，对话角色前缀已经超过它。新建对话模型改为 64，最大上下文保持 256，参数数量不变。旧存档仍按自己的配置加载。
6. 固定验证原来只覆盖 0–19 加 0–9。现在 1/2/4/6/10 位各 40 题，另显示 token 正确率、CE 与分长度分数。各组包含零、边界和固定种子随机题，因此“十位组一题正确”可能只是 0+0，不能宣称掌握十位加法。
7. QAT 开始前保存并评估实际输入模型；量化导致退步时保留较好的输入模型（可能仍是 FP32）。FP4 最后更新另存，供比较。页面不再把阶段结束叫作 FP4 成品。

旧奇怪格式之所以容易工作，还因为外部调度器负责逐列迭代、传递进位和拼接答案；完整 user/assistant 自回归需要模型自己学会这些操作。改格式后的相同步数不能当作收敛保证。现有旧协议成品保留，没有用它替换新对话实验。

## 实际完整复跑

随机种子 20261018，CoT 开启，阶段步数依次为 200/3000/3000/3000/400/2000。原生复现工具的所有阶段 **batch=4**；网页默认 QAT batch=8，本报告不将两者说成完全相同配置。

```powershell
ai-add/build/chat_run.exe ai-add/web/build/train-after-final 1 200 3000 3000 3000 400 2000 4
ai-add/build/chat_eval.exe ai-add/web/build/train-after-final/stage-6.cn 1 ai-add/web/build/training-comparison train-after-final-stage-6
```

修改前同预算模型保存在 `build/train-before`。修改前旧验证集的曲线：SFT 3 曾达到 100/200，最后归零；QAT 中途 61/200，最后归零。这只能用于观察其自身退化，不能与新版验证集分数直接比较。

## 可检查的产物

- `build/training-diagnosis.json`：前后曲线、统一验证结果和五道实际生成题。
- `build/training-comparison/*-metrics.json`、`*-sample-*.txt/json`：独立加载模型的验证与原始生成。
- `build/train-after-final/stage-N-entry.cn`、`stage-N-last.cn`、`stage-N.cn`：六阶段实际权重，均含优化器；同名 `.aiadd` 包保留 chat-v1 与 CoT 元数据，可直接在网页“导入模型”测试和续训。
- `build/validation-training-repair-native.log`、`build/validation-training-repair-asan.log`：Windows 与 Linux ASan/UBSan/leak 均 14/14。
- `build/validation-training-repair.json`：WASM SIMD/标量流程回归。
- `build/browser-training-repair.json`：最终浏览器滚动、选择删除/撤销、刷新恢复、三版本保存与失败推理检查。

固定验证集参与了模型选择，不是独立测试集，也不能用于证明任意位正确。以上修复解决已复现的流程错误；对话模型的长位数能力仍需继续研究训练配方与预算，页面保留所有失败权重便于观察。
