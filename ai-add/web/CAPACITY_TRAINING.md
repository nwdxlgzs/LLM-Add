# 六层扩容实验（dialogue-v5）

按用户要求扩大已有 DSV4.1F 缩小网络。保持六层、3+3 Causal Encoder-Decoder、SWA、CSA2 Full/Reuse/Reindex、MoE 2+1、Engram、mHC2、RoPE 和 261 类词表。没有视觉塔。

训练仍是一条完整 user 问题，assistant 自回归生成用户指定的 `pos=1 a=9 b=7 cin=0 -> 6 1` 格式和最终答案。所有取位、进位、步骤和答案由网络生成。评测中的加法只判分；没有输出掩码、外部逐列推理或算术兜底。

时间是在本机原生 C Release 单序列训练上实测，每档重复 12 次，不含整套训练期间的验证。不是跨机器速度保证。原始结果见 `build/capacity-v5/pilots.json`。本轮约 9.6 倍参数、2.3 倍单序列耗时，FP32 权重约 2.1 MiB，仍只用 CPU。

`add_chat_resize()` 同步调整主干、注意力、低秩投影、索引器和 Engram；FFN 独立可设。dim24/FF24 完全保留原配置。网页支持 dim16/24/32/48/64/96/128，以及 FF16..512 的常用档位。导入历史检查点恢复文件里的精确维度，不重解释为新尺寸。

## 同预算对照

协议 chat-v2、上下文/窗口 512、种子 20261018、CoT、batch4。六阶段步数与 dialogue-v4 一致：600/2400/4000/8000/200/600。数据生成、数字加权 CE、长度课程、RLOO 奖励与验证选模规则均不改变；此轮仅调整模型宽度。

```powershell
ai-add/build/chat_run.exe ai-add/web/build/dialogue-v5-run 1 600 2400 4000 8000 200 600 4 new 1 3 4 64 128
python ai-add/web/publish-dialogue.py --version v5
python ai-add/web/test-dialogue-native.py --version v5
python ai-add/web/compare-capacity.py
python ai-add/web/build.py --emsdk D:/project/emsdk-3.1.69
node ai-add/web/test-dialogue-wasm.cjs
node ai-add/web/test-parity.cjs --capacity --fields
```

原生训练目录保留各阶段的入口、最后更新、验证选择（含优化器和 `.aiadd` 元数据）。历史 v4 和用户本地检查点保留；网页内置仍仅六个本轮阶段，自己的训练单列。

原生训练及其验证共 4,051.4 秒（约 67.5 分钟）。每阶段入口、最后更新、选择权重全部保留，RLOO 有 35 轮奖励差异，选择入口；QAT 最后 154/200，比 FP32 入口 153/200 高 1 题，实际选择精度为 FP4。

## 独立同题测试

随机种子 938234，每档 20 道真实位数随机题，逐题与 v4 一致。测试只按最终答案判分；所有 token/原文和逐字段诊断保留在 `build/dialogue-v5-tests/`。按列统计时，取数要求 a/b 同时正确，完整步骤还要求位置、输入进位及局部转移正确。

|位数|原 57,388 参数答案|本轮 550,556 参数答案|本轮正确取数列|
|---:|---:|---:|---:|
|1|20/20|20/20|20/20|
|2|10/20|20/20|40/40|
|4|0/20|20/20|80/80|
|6|0/20|19/20|114/120|
|10|0/20|3/20|181/200|
|12|0/20|0/20|6/240|
|20|0/20|0/20|0/400|

扩容显著改善训练长度内的取数与运算，但**没有学会稳定十位或任意位加法**。十位随机取数从 8/200 升到 181/200 列，整题仍只有 3/20。训练只覆盖到十位，十二位以上的格式和定位泛化仍失败。

- `90+70` 从错误的 161 变成正确的 160，包含用户指定的 `pos=1 a=9 b=7 cin=0 -> 6 1`。
- `9999999999+1` 十个步骤及最终 `10000000000` 正确。
- `7140345462+1095133250` 最终为 8835778712，仍错；十行位置、输入进位和相对所生成操作数的运算均对，8/10 行取数正确，2 列取错。
- `9999999999+9999999999` 十行步骤都对，最终却为 199999999989，答案汇总仍有错误。

独立题集不参与选模。FP4 比 FP32 在固定验证高 1 题，不等于所有题型或长度都更好。

## 引擎数值边界

原生 C 与 WASM 使用同一训练源。比较包含固定输入的 logits、实际梯度更新、Adam 状态、优化器互载和真实连续生成，使用公开数值容差。

随机 FP4 QAT 在此宽度下存在原生 auto 与 WASM SIMD 也不一致的反例；量化阈值和离散选择放大浮点差异，不能声称所有 ISA 或量化训练轨迹完全等效。最终 FP4 的跨后端 logit 对照也未过容差，固定 teacher-forcing 探针 argmax 全相同；这不代表自由长轨迹必然相同。失败对照保存在 `build/parity-v5/report.json`，不会因换模型尺寸删除历史 v4 的反例。FP32 与 QAT、前向 token 一致性分别报告。

扩容后的 FP32 预填、随机 masked SFT、已训 SFT 和真实 RLOO（含 Adam 状态与互载）在声明容差内通过。最终 FP4 在原生 C/WASM 标量代表样例中有百位滚动生成分歧；随机题也有少数 token 分歧，不能声称该权重任意输入逐字相同。协议/训练流程检查与生成等效检查分别记分，完整报告保留整体 `passed=false`。
